# java-main

第五人格（祭司主题）登录 / 注册演示项目。

| 部分 | 目录 | 技术栈 | 端口 |
|---|---|---|---|
| 后端 | `springBootTest` | Spring Boot 3.4.5 + MyBatis-Plus 3.5.9 + MySQL 8 | **8081** |
| 前端 | `第五人格` | Vue 3 + Vite 5 | **5173** |

数据库：MySQL 库 `idv_auth`，表 `t_user`（昵称 / BCrypt 密码 / 状态 / 时间）。

> **注册不需要手机号，也不需要短信验证码**（已按要求移除）。

---

## 快速开始

> 这台电脑每次开机都会重置（数据库会丢），所以**每次开机都要重新启动一遍**。

**双击 `启动全部.bat`** 就行。它会自动：

1. 启动 MySQL80 服务
2. 建库建表（`springBootTest\sql\init.sql`）
3. 打开两个窗口，分别启动后端和前端

等十几秒后访问：

- 前端 → <http://localhost:5173>（会自动进登录页）
- 后端首页 → <http://localhost:8081>

**第一次用**：先点「注册新身份」注册一个账号，注册成功会**自动登录**并进入用户中心。

**停止**：双击 `停止全部.bat`（MySQL 服务会保持运行）。

## 页面

| 页面 | 地址 | 说明 |
|---|---|---|
| 登录 | `/login` | 账号 = 注册时填的昵称；已登录会自动跳到用户中心 |
| 注册 | `/register` | 昵称 + 密码 + 确认密码，成功后自动登录 |
| 用户中心 | `/home` | 需登录才能进；可查看自己的信息、校验登录态、退出登录 |

「用户中心」里的 **校验登录态** 按钮会带着令牌去请求后端的受保护接口，用来看登录态是不是真的生效。

## 接口

### 1. 注册

```
POST /api/auth/register
Content-Type: application/json

{ "nickname": "你的昵称", "password": "8-20位含字母和数字" }
```

### 2. 登录

```
POST /api/auth/login
Content-Type: application/json

{ "nickname": "你的昵称", "password": "你的密码" }
```

成功返回：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9....",
    "tokenType": "Bearer",
    "expiresIn": 7200,
    "user": { "id": 1, "nickname": "祭司", "status": 0, "createdAt": "2026-10-09T14:57:29" }
  }
}
```

`token` 就是登录凭据，**默认 2 小时有效**。

### 3. 当前登录用户（需要令牌）

```
GET /api/user/me
Authorization: Bearer {上一步拿到的 token}
```

### 错误码约定

| code | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 参数不合法（如昵称为空） |
| 401 | 账号或密码错误 / 未登录 / 令牌过期或伪造 |
| 403 | 账号已被禁用 |
| 409 | 昵称已被注册 |
| 500 | 服务端异常 |

> ⚠️ 业务出错时 **HTTP 状态码仍然是 200**，真正的结果要看响应体里的 `code` 字段。
> 用浏览器 / Postman 直接看状态码会以为「怎么都是成功的」。

### 登录是怎么保持的

后端签发 JWT（无状态，服务器不存 session），前端把令牌存在浏览器 `localStorage` 里，
之后每次请求由 `src/api/http.js` 自动加上 `Authorization` 请求头。
令牌过期后第一个请求会返回 401，前端会自动清掉登录态并让用户重新登录。

> 退出登录只是前端把令牌删掉（JWT 无状态，服务端不需要通知）。
> 生产环境通常还会做「令牌黑名单」或改用短期令牌 + 刷新令牌。

## 后端也自带一套完整网页（不依赖前端）

除了给前端调用的接口，后端自己还有一套 **Thymeleaf 页面流程**，用传统的 Session 保持登录态，
不需要起前端就能直接打开浏览器走完「注册 → 登录 → 用户主页 → 退出」：

| 页面 | 地址 | 说明 |
|---|---|---|
| 首页 | <http://localhost:8081/> | 带「登录 / 注册」两个入口 |
| 注册 | `/register` | 昵称 + 密码 + 确认密码；成功后 **302 跳登录页**，昵称帮你填好 |
| 登录 | `/login` | 账号（=昵称）+ 密码；成功后 **302 跳用户主页** |
| 用户主页 | `/home` | **需要登录**；未登录会被重定向到 `/login?redirect=/home`，登录后自动跳回来 |
| 退出 | `POST /logout` | 清掉会话，**302 跳回登录页** |

密码同样用 BCrypt 存进 `t_user`，校验也走同一套 `UserService` —— 所以
**在网页上注册的账号，可以直接拿去前端登录页登录**（反过来也一样）。
两套登录态（页面 Session / 接口 JWT）互不共享，但账号是共用的。

> 后端自带的旧欢迎页还在，只是根路径被首页接管了，要看得显式访问 <http://localhost:8081/index.html>。

## 环境依赖

JDK 17+（本机是 Zulu 21）、MySQL 8、Node.js 18+。
本机没有安装 `mvn` 命令，脚本用的是项目自带的 `mvnw.cmd` 或本机缓存的 Maven。

更详细的环境路径、命令行启动方式、踩过的坑，见 **[`AI-README.md`](AI-README.md)**（那份是写给 AI 助手看的，自己排错时也很有用）。
